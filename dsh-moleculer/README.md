# `dsh-moleculer`

Интеграция с [Moleculer](https://moleculer.services/): плагин поднимает узел
сети внутри DeepSeek Harness, даёт ИИ **три инструмента** для работы с сетью
и сообщает работающей модели, когда сеть меняется.

## Что делает

- **Поднимает брокер** при старте и соединяется с другими узлами по
  TCP/NATS/Redis/MQTT/AMQP. Параметры подключения — **Settings → Plugins →
  карточка «Moleculer mesh» / «Сеть Moleculer»**.
- **Даёт ИИ три инструмента, а не по инструменту на действие.** Сеть может
  публиковать сотни действий; если сделать каждое отдельным инструментом, все
  их описания уезжают в **каждый** запрос модели, и контекст распухает ещё до
  того, как что-то понадобилось. Поэтому поверхность фиксированная и маленькая:
  - `mesh_list` — какие сервисы и какие у них действия (имена, без схем;
    необязательный `service` — фильтр);
  - `mesh_describe` — схема параметров одного действия (`action`);
  - `mesh_call` — вызвать действие (`action`, `params`).

  Каталог запрашивается по требованию, поэтому стоимость контекста
  пропорциональна тому, о чём модель действительно спросила, а не размеру сети.
  Действия самого узла (`$node.list`, `$node.health`, `$node.services`, …)
  видны там же обычными именами и вызываются через `mesh_call`.
- **Отдаёт тот же набор по MCP** — эндпоинт `POST /api/moleculer/mcp`
  (Streamable HTTP), то есть к сети может подключиться любой внешний
  MCP-клиент, а не только этот харнесс.
- **Управляется из чата командой `/moleculer`**: без аргументов или
  `status` — показать состояние сети, `start` / `stop` / `restart` —
  поднять, остановить или перезапустить узел по текущим настройкам.
- **Оповещает модель.** Когда узел присоединяется, уходит или меняет набор
  сервисов, каждому агенту, который **сейчас работает над задачей**,
  подставляется сообщение вида
  `[Moleculer mesh] Node x joined the mesh. Moleculer mesh "dsh": 2 node(s)…
  Call mesh_list to see the current actions.`
  Отдыхающие агенты не будятся: иначе плагин создавал бы ходы, которых никто
  не просил.

## Как работает

- **Брокер** (`lib/index.js`) стартует из настроек харнесса и живёт в его
  процессе. Старт **не блокирует** загрузку харнесса: недоступный сосед не
  должен задерживать boot, поэтому ошибка пишется в лог, а сеть просто
  остаётся пустой.
- **Каталог** (`lib/mesh.js`) — чистый слой: настройки, отбор сервисов,
  поиск действия по имени (принимает и `orders.create`, и `orders_create`) и
  превращение `params` действия Moleculer в JSON Schema. Тесты на него не
  поднимают сеть.
- **Инструментов ровно три, и они регистрируются один раз.** Набор не зависит
  от реестра, поэтому появление или уход сервиса не трогает список
  инструментов модели: он читает живое состояние в момент вызова. Остановка
  брокера инструменты не снимает — они просто отвечают, что сеть не запущена.
- **Настройки** хранит харнесс (`ctx.settings.register`), плагин только читает
  и пишет секцию `dsh-moleculer`: `namespace`, `transporter`, `host`, `port`,
  `nodeID`, `peers`.

### Почему `peers` и порт — разные вещи

`port`/`host` — это адрес, **на котором узел слушает**. `peers` — адреса,
**куда он звонит сам**. Собственный адрес из `peers` вырезается: иначе
Moleculer бесконечно переподключается к собственному сокету, и узел
«зависает» ещё до того, как успел стать частью сети.

### Что именно уходит в MCP

Те же три инструмента — `mesh_list`, `mesh_describe`, `mesh_call` — и никаких
`mesh_<сервис>_<действие>`. Схема `mesh_call` — `action` плюс свободный
`params`: схему конкретного действия модель получает из `mesh_describe`,
поэтому описания сотен действий не попадают ни в `tools/list`, ни в контекст.
Если действие не найдено, `mesh_call` отвечает ошибкой и подсказывает вызвать
`mesh_list`.

## Установка

```sh
git clone https://github.com/westtrade/deepseek-harness-plugins ~/deepseek-harness-plugins
cd ~/deepseek-harness-plugins && npm install      # moleculer + MCP SDK
mkdir -p ~/.dsh/profiles/node_modules
ln -sfn ~/deepseek-harness-plugins/dsh-moleculer ~/.dsh/profiles/node_modules/dsh-moleculer
```

```yaml
- insert:
    - id: moleculer
      name: 'file:///home/USER/.dsh/profiles/node_modules/dsh-moleculer/lib/index.js?rev=1'
```

Зависимости лежат в корне репозитория намеренно: плагин загружается по
симлинку и разрешает импорты относительно **реального** пути, поэтому
`node_modules` рядом с репозиторием — единственное место, откуда он увидит
`moleculer` и MCP SDK.

## Где настройки в интерфейсе

**Settings → Plugins** (вкладка Plugins, секция «Plugin configuration»),
карточка **«Сеть Moleculer»** / **«Moleculer mesh»**. Она свёрнута по умолчанию
и разворачивается кликом по заголовку — так же, как карточки остальных
плагинов (тот же chevron, тот же радиус 16px, тот же отступ заголовка).
Внутри: поля
`namespace`, `transporter`, `host`, `port`, `nodeID`, `peers`, кнопка
**Применить** и живое состояние сети под ними.

Карточка появляется, только если хост отдаёт namespace в `settings.describe()`:
этот вызов сериализует схему через `schema.toJSON()`, поэтому схема обязана
его иметь (см. `lib/index.js`, `settingsSchema`).

## Настройки

| Поле | По умолчанию | Смысл |
|---|---|---|
| `namespace` | `dsh` | сеть, в которой видны узлы |
| `transporter` | `TCP` | `TCP`, `NATS`, `Redis`, `MQTT`, `AMQP` |
| `host` | `127.0.0.1` | адрес, на котором узел слушает |
| `port` | `6174` | порт прослушивания (Moleculer по умолчанию) |
| `nodeID` | пусто | id узла; пусто — Moleculer сгенерирует |
| `peers` | пусто | через запятую: адреса, куда подключаться |

## Маршруты

| Метод и путь | Назначение |
|---|---|
| `GET /api/moleculer/state` | живое состояние сети, каталог действий, имена инструментов, сводка |
| `POST /api/moleculer/mcp` | MCP (Streamable HTTP): `initialize`, `tools/list`, `tools/call` |

Поле `command` в ответе состояния говорит, зарегистрирована ли команда
`/moleculer` — она требует сервиса `commands` и без него просто не появляется,
не мешая остальному плагину.

## Проверка

```sh
node scripts/mesh-test.mjs   # каталог, поиск действия, схемы, три инструмента
node scripts/host-test.mjs   # брокер, инструменты, команда, оповещение
node scripts/client-smoke.mjs# обвязка карточки настроек
curl -s http://127.0.0.1:3080/api/moleculer/state
```

Живьём проверено: узел поднимается, `mesh_list` перечисляет `$node` и его
действия, `mesh_call { action: "$node.health" }` возвращает настоящие данные
системы, а оповещение о старте сети приходит в контекст работающего агента.

## Ограничения

- MCP-сервер собирается на каждую HTTP-сессию. Набор инструментов у него
  фиксированный (три штуки), поэтому переподключаться из-за изменений сети не
  нужно — меняется только ответ `mesh_list`.
- Публикуются все сервисы, включая внутренние `$node`. Это сделано
  намеренно, но если в сети появятся сервисы, которые ИИ видеть не должен,
  понадобится список исключений.
- `mesh_list` отдаёт только имена, без схем: чтобы контекст не рос с размером
  сети, схему одного действия нужно запросить через `mesh_describe`.
- Транспорты кроме TCP требуют соответствующей инфраструктуры (NATS, Redis,
  MQTT, AMQP) и установленных пакетов Moleculer для них.
