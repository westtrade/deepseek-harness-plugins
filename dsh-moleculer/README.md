# `dsh-moleculer`

Интеграция с [Moleculer](https://moleculer.services/): плагин поднимает узел
сети внутри DeepSeek Harness, публикует сервисы сети для ИИ **как MCP** и
сообщает работающей модели, когда сеть меняется.

## Что делает

- **Поднимает брокер** при старте и соединяется с другими узлами по
  TCP/NATS/Redis/MQTT/AMQP. Параметры подключения — в **Settings** харнесса
  (вкладка Plugins, карточка **Moleculer mesh**).
- **Публикует сервисы как инструменты.** Каждое действие сети становится
  инструментом модели: `mesh_<сервис>_<действие>`. Первыми идут действия
  самого узла (`$node`), потому что через них можно спросить сеть о себе:
  `mesh_node_health`, `mesh_node_services`, `mesh_node_actions`,
  `mesh_node_events`, `mesh_node_metrics`, `mesh_node_options`,
  `mesh_node_list`.
- **Отдаёт тот же набор по MCP** — эндпоинт `POST /api/moleculer/mcp`
  (Streamable HTTP), то есть к сети может подключиться любой внешний
  MCP-клиент, а не только этот харнесс.
- **Управляется из чата командой `/moleculer`**: без аргументов или
  `status` — показать состояние сети и инструменты, `start` / `stop` /
  `restart` — поднять, остановить или перезапустить узел по текущим
  настройкам.
- **Оповещает модель.** Когда узел присоединяется, уходит или меняет набор
  сервисов, каждому агенту, который **сейчас работает над задачей**,
  подставляется сообщение вида
  `[Moleculer mesh] Node x joined the mesh. Moleculer mesh "dsh": 2 node(s)…`.
  Отдыхающие агенты не будятся: иначе плагин создавал бы ходы, которых никто
  не просил.

## Как работает

- **Брокер** (`lib/index.js`) стартует из настроек харнесса и живёт в его
  процессе. Старт **не блокирует** загрузку харнесса: недоступный сосед не
  должен задерживать boot, поэтому ошибка пишется в лог, а сеть просто
  остаётся пустой.
- **Каталог** (`lib/mesh.js`) — чистый слой: настройки, отбор сервисов и
  превращение `params` действия Moleculer в JSON Schema. Тесты на него не
  поднимают сеть.
- **Инструменты** пересобираются при каждом изменении сети: сначала строится
  весь новый набор, потом он подменяет старый. Сбой при построении оставляет
  прежние инструменты, поэтому случайная ошибка реестра не отнимает у модели
  инструменты.
- **Настройки** хранит харнесс (`ctx.settings.register`), плагин только читает
  и пишет секцию `dsh-moleculer`: `namespace`, `transporter`, `host`, `port`,
  `nodeID`, `peers`.

### Почему `peers` и порт — разные вещи

`port`/`host` — это адрес, **на котором узел слушает**. `peers` — адреса,
**куда он звонит сам**. Собственный адрес из `peers` вырезается: иначе
Moleculer бесконечно переподключается к собственному сокету, и узел
«зависает» ещё до того, как успел стать частью сети.

### Что именно уходит в MCP

Имена очищаются до `[A-Za-z0-9_-]` и 64 символов (таково требование
реестра инструментов харнесса), поэтому `$node.list` становится
`mesh_node_list`. Параметры берутся из описания действия: типы `string`,
`number`, `boolean`, `array`, `object`; всё остальное пропускается, а не
угадывается — неверная схема хуже свободной.

## Установка

```sh
git clone https://github.com/westtrade/deepseek-harness-plugins ~/deepseek-harness-plugins
cd ~/deepseek-harness-plugins && npm install      # moleculer + MCP SDK
mkdir -p ~/.dsh/profiles/node_modules
ln -sfn ~/deepseek-harness-plugins/dsh-moleculer ~/.dsh/profiles/node_modules/dsh-moleculer
```

```yaml
- insert:
    - id: moleculer
      name: 'file:///home/USER/.dsh/profiles/node_modules/dsh-moleculer/lib/index.js?rev=1'
```

Зависимости лежат в корне репозитория намеренно: плагин загружается по
симлинку и разрешает импорты относительно **реального** пути, поэтому
`node_modules` рядом с репозиторием — единственное место, откуда он увидит
`moleculer` и MCP SDK.

## Настройки

| Поле | По умолчанию | Смысл |
|---|---|---|
| `namespace` | `dsh` | сеть, в которой видны узлы |
| `transporter` | `TCP` | `TCP`, `NATS`, `Redis`, `MQTT`, `AMQP` |
| `host` | `127.0.0.1` | адрес, на котором узел слушает |
| `port` | `6174` | порт прослушивания (Moleculer по умолчанию) |
| `nodeID` | пусто | id узла; пусто — Moleculer сгенерирует |
| `peers` | пусто | через запятую: адреса, куда подключаться |

## Маршруты

| Метод и путь | Назначение |
|---|---|
| `GET /api/moleculer/state` | живое состояние сети, список инструментов, сводка |
| `POST /api/moleculer/mcp` | MCP (Streamable HTTP): `initialize`, `tools/list`, `tools/call` |

Поле `command` в ответе состояния говорит, зарегистрирована ли команда
`/moleculer` — она требует сервиса `commands` и без него просто не появляется,
не мешая остальному плагину.

## Проверка

```sh
node scripts/mesh-test.mjs   # каталог: настройки, имена, схемы: 25
node scripts/host-test.mjs   # брокер, инструменты, команда, оповещение: 33
node scripts/client-smoke.mjs# обвязка карточки настроек: 16
curl -s http://127.0.0.1:3080/api/moleculer/state
```

Живьём проверено: узел поднимается, `$node` даёт 7 инструментов, по MCP
`tools/call mesh_node_health` возвращает настоящие данные системы, а
оповещение о старте сети приходит в контекст работающего агента.

## Ограничения

- MCP-сервер собирается на каждую HTTP-сессию, и его набор инструментов —
  снимок на момент подключения. Внешний MCP-клиент увидит новые сервисы
  после переподключения; инструменты **модели** обновляются сразу.
- Публикуются все сервисы, включая внутренние `$node`. Это сделано
  намеренно, но если в сети появятся сервисы, которые ИИ видеть не должен,
  понадобится список исключений.
- Транспорты кроме TCP требуют соответствующей инфраструктуры (NATS, Redis,
  MQTT, AMQP) и установленных пакетов Moleculer для них.
