# `dsh-project-cost`

Проектный учёт расходов для DeepSeek Harness: плагин считает, **сколько денег
потрачено на каждый проект (директорию)**, по ценам [routerai.ru](https://routerai.ru/),
и показывает сумму **напротив директории** в веб-интерфейсе.

## Что делает

- **Хост-часть** (`lib/index.js` + `lib/report.js`) сканирует сохранённые
  логи сессий (`~/.dsh/sessions/**/session.v*.jsonl(.zstd)`), сворачивает
  провайдерский учёт токенов (`usage` событий `assistant/message`) в разрезе
  моделей и оценивает его по прайсу routerai.ru. Тот же свёрток даёт **цену
  каждого хода** (`sessions[].turns`), которой пользуются бейджи чата.
- **Клиентская часть** (`lib/client.js`) добавляет:
  - **бейджи в дереве Workspaces** — сумма справа в каждой строке: у директории
    её общий расход, у сессии — расход этой сессии **рядом с временем справа**;
  - **стоимость в строке метрик чата** — под каждым ответом ассистента после
    «Usage … / Ran for … / времени» дописывается цена этого хода. Берётся она
    из хост-отчёта (та же арифметика, что у дерева и панели), поэтому бейдж
    есть **и у ходов без доказуемого `Usage` и без атрибуции модели** — то
    есть и у прерванных/повторённых ходов вида «Ran for 39m 38s». Ход, который
    отчёт ещё не успел просканировать (живой), оценивается по пилюле `Usage`
    через `/api/project-cost/prices`, а если и этого роута нет — по каталогу
    routerai.ru напрямую (CORS `*`); ход без цены остаётся без бейджа;
  - строку **«Project costs»** в списке панелей сайдбара — слева иконка,
    справа **общая потраченная сумма**; клик открывает панель
    **«Project costs»** с таблицей «директория … потрачено ₽».
- **CLI** (`scripts/report.mjs`) печатает тот же отчёт в терминале.

## Как считается стоимость

Для каждого `assistant/message` с `usage` берутся раздельные (по контракту
DSH) счётчики: некэшированный вход `inputTokens`, выход `outputTokens`, а
также `cacheReadTokens` / `cacheWriteTokens`. Цена — из публичного каталога
`https://routerai.ru/api/v1/models` (рубли за один токен: `pricing.prompt`,
`pricing.completion`, `pricing.input_cache_read`, `pricing.input_cache_write`):

```
стоимость = inputTokens × prompt
          + outputTokens × completion
          + cacheReadTokens × input_cache_read
          + cacheWriteTokens × input_cache_write
```

Если каталог не указывает цену кэша, кэшированные токены считаются по полной
цене входа (консервативная верхняя граница). Модели вне каталога отмечаются
как `unpriced` и в сумму не входят — они перечислены в отчёте. Если один ход
шёл через несколько моделей, браузерские счётчики агрегированы без разбивки
по роутам — такой ход в строке метрик оценивается по тарифу первой модели.

Учитываются только события после последнего маркера
`session/end-seed { inherited: true }`: у форк-ребёнка префикс, унаследованный
от родителя, не считается повторно.

## Установка в профиль

```sh
# 1. клонировать репозиторий (или указать путь к своей копии)
git clone https://github.com/westtrade/deepseek-harness-plugins ~/deepseek-harness-plugins

# 2. сделать пакет видимым из профиля
mkdir -p ~/.dsh/profiles/node_modules
ln -sfn ~/deepseek-harness-plugins/dsh-project-cost \
        ~/.dsh/profiles/node_modules/dsh-project-cost

# 3. добавить строку в слой патча профиля (~/.dsh/profiles/web/cordis.patch.yml)
#    - insert:
#        - id: project-cost
#          name: 'dsh-project-cost'
```

При `patchReload: live` (по умолчанию у кастомных профилей) слой патча
применяется на лету; затем достаточно обновить страницу GUI. Без live-режима —
перезапустить `dsh web`.

### Горячая перезагрузка кода плагина

Строка патча указывает entry **полным `file://` URL** с query-строкой:

```yaml
name: 'file:///home/USER/.dsh/profiles/node_modules/dsh-project-cost/lib/index.js?rev=7'
```

`?rev=…` обнуляет ESM-кэш всего локального графа модулей (`lib/index.js`
прокидывает query в `report.js` → `scan.js`/`prices.js`/`cost.js`), поэтому
правки хост-кода подхватываются **без перезапуска сервера**: увеличьте `rev`
— HMR заметит изменение файла патча и перечитает плагин (число неважно, важна
смена строки). Клиентский бандл перечитывается сам (`dsh-client-hmr`).

Тонкость, из-за которой правки молча не доезжали: загрузчик патча прогоняет
**относительное или абсолютное** имя entry через `pathToFileURL()`, а тот
percent-кодирует `?` в `%3F` — файл «не найден», импорт падает и весь
патч-релоад откатывается на прежнюю копию. Форма `file://` под перезапись не
попадает (не выглядит как путь), поэтому query выживает. Если правите патч —
держите `file://`-форму.

## Проверка

```sh
curl -s http://127.0.0.1:3080/api/project-cost | head -c 400
node scripts/report.mjs        # тот же отчёт в терминале
node scripts/report.mjs --json # сырой JSON
```

## Конфигурация (поле `config` строки патча)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `cacheTtlMs` | `30000` | сколько отчёт кэшируется для опроса GUI |
| `sessionsRoot` | `$DSH_HOME/sessions` | где искать логи сессий |
| `priceCachePath` | `$DSH_HOME/project-cost-prices.json` | дисковый кэш прайса |
| `priceUrl` | `https://routerai.ru/api/v1/models` | источник прайса |

Прайс: живой запрос → дисковый кэш → встроенный снапшот
(`lib/prices.snapshot.json`) — офлайн-режим тоже считает.

## Ограничения

- `usage` событий `session/title-llm-request` не публикуется — генерация
  заголовков в сумму не входит (это копейки).
- Стоимость — оценка по прайсу routerai.ru, а не выписка из биллинга
  провайдера; кэш-тарифы моделей без собственной ставки округляются вверх.
- Форк-дети: унаследованный от родителя префикс не считается повторно в
  итогах, но цены его ходов всё равно показываются в чате ребёнка (там этот
  транскрипт виден).
