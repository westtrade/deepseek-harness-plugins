# `dsh-cron-schedule`

Планировщик задач для DeepSeek Harness: **в заданное время создаётся новый чат
в выбранном каталоге и получает задачу для ИИ**. Есть панель управления в
веб-интерфейсе и инструменты, которыми ИИ сам может завести расписание.

## Что делает

- **Панель «AI schedules»** в сайдбаре (рядом с другими панелями) — таблица
  задач: имя, расписание, следующий запуск, каталог, действия. Кнопки
  **Run now / Disable / Delete** у каждой задачи, выбор каталога **селектором
  из сохранённых workspace или файлпикером ОС**, поле задачи для ИИ и живой
  предпросмотр ближайших запусков по мере ввода выражения.
- **Расписание**: пресеты в интерфейсе (каждый час, каждые 30 минут, ежедневно
  в 09:00, по будням, по понедельникам, 1-го числа) **или** произвольное
  cron-выражение.
- **Запуск**: в момент срабатывания создаётся **новый чат** в указанном
  каталоге, ему отправляется текст задачи как первое сообщение пользователя.
  Чат появляется в общем списке сессий как обычный — со своей моделью, правами
  и пресетом, — а в логе помечен `source.kind: "cron"`.
- **Пропущенные запуски**: если DSH был выключен, панель показывает баннер
  «столько-то запусков пропущено» со списком времён и кнопками **Выполнить** и
  **Пропустить**. Автоматически ничего не догоняется.
- **Инструменты для ИИ** (модель видит их как обычные тулы):

  | Инструмент | Назначение |
  |---|---|
  | `cron_list` | список расписаний с id, состоянием, описанием и следующим запуском |
  | `cron_create` | создать расписание (каталог по умолчанию — текущий каталог сессии) |
  | `cron_describe` | объяснить выражение и показать ближайшие запуски, ничего не сохраняя |
  | `cron_run` | запустить расписание немедленно, не сдвигая график |
  | `cron_delete` | удалить расписание по id |

## Установка

```sh
git clone https://github.com/westtrade/deepseek-harness-plugins ~/deepseek-harness-plugins

mkdir -p ~/.dsh/profiles/node_modules
ln -sfn ~/deepseek-harness-plugins/dsh-cron-schedule \
        ~/.dsh/profiles/node_modules/dsh-cron-schedule
```

Затем добавьте строку в слой патча профиля
(`~/.dsh/profiles/web/cordis.patch.yml`):

```yaml
- insert:
    - id: cron-schedule
      name: 'file:///home/USER/.dsh/profiles/node_modules/dsh-cron-schedule/lib/index.js?rev=1'
      config:
        locale: ru
```

Обновите страницу GUI. Без `patchReload: live` — перезапустите `dsh web`.

### Почему `file://` и `?rev=`

Загрузчик патча прогоняет **относительное или абсолютное** имя через
`pathToFileURL()`, а тот превращает `?` в `%3F` — файл «не найден», импорт
падает, и весь патч-релоад молча откатывается на прежнюю копию. Форма
`file://` под перезапись не попадает, поэтому query выживает, и **увеличение
`rev` перечитывает код без перезапуска сервера**. `lib/index.js` прокидывает
этот query и в свои импорты (`store.js`, `scheduler.js`, `runner.js`,
`cron.js`) — иначе перечитается только входной файл, а вложенные модули
останутся старыми.

## Как работает

- **Расписание** — свой cron-движок (`lib/cron.js`) без зависимостей: пять
  полей, диапазоны, списки, шаги, имена месяцев и дней, `@daily`-макросы,
  `0`/`7` = воскресенье и правило Vixie «день месяца ИЛИ день недели». Расчёт
  идёт по настенным часам выбранного пояса IANA, поэтому переход на летнее
  время не сдвигает задачу.
- **Планировщик** (`lib/scheduler.js`) держит **один** таймер на ближайшую
  задачу, пересчитывая время от настенных часов на каждом пробуждении. Задержка
  ограничена максимумом `setTimeout` (~24,8 суток) — задача на месяцы вперёд
  всё равно сработает.
- **Хранилище** (`lib/store.js`) — один JSON-файл `$DSH_HOME/cron-schedule.json`,
  запись через временный файл и `rename`, поэтому сбой не оставит
  полузаписанный список. Битый файл читается как пустой, а не роняет плагин.
- **Запуск** (`lib/runner.js`) повторяет путь кнопки «новый чат» в GUI:
  `workspaceRegistry.create` → `agents.create({meta: {cwd, agentPreset},
  agentOptions})` → `attachSession` → `followup(сообщение)`. Неудачный запуск
  откатывает созданную сессию, чтобы не осталось чата-призрака.

### Особенность загрузки плагинов

Плагин намеренно **не импортирует ничего, кроме `node:`** — ни `zod`, ни
пакеты `@deepseek-ai/*`. Плагин, загруженный через симлинк из рабочего
каталога, резолвится в свой реальный путь, откуда пакеты харнесса недоступны
(`ERR_MODULE_NOT_FOUND`). Все возможности харнесса берутся через сервисы
`ctx`, а `defineTool`/`domainTable` заменены их прямыми контрактами. Побочная
выгода — плагин работает и как обычный пакет, без сборки.

## Конфигурация (поле `config` строки патча)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | запускать планировщик; `false` — только панель и инструменты |
| `storePath` | `$DSH_HOME/cron-schedule.json` | файл хранилища |
| `home` | `$DSH_HOME` или `~/.dsh` | каталог для хранилища |
| `locale` | `ru` | язык описаний расписаний (`ru` / `en`) |

## HTTP-маршруты (для панели)

| Метод и путь | Назначение |
|---|---|
| `GET /api/cron-schedule/jobs` | список задач |
| `POST /api/cron-schedule/jobs` | создать задачу |
| `POST /api/cron-schedule/jobs?action=dismiss-missed` | очистить список пропущенных |
| `GET /api/cron-schedule/jobs/<id>` | одна задача |
| `POST /api/cron-schedule/jobs/<id>` | изменить (в том числе `{"enabled": false}`) |
| `POST /api/cron-schedule/jobs/<id>/run` | запустить немедленно |
| `DELETE /api/cron-schedule/jobs/<id>` | удалить |
| `POST /api/cron-schedule/jobs/preview` | описание и ближайшие запуски выражения |

## Ограничения

- Задача запускается, только пока работает `dsh web`; пропущенное время
  отмечается баннером, а не догоняется молча.
- Время считается по настенным часам пояса задачи. Если local time попадает в
  «дыру» перехода на летнее время, в этот день запуск пропускается — так же
  поступает классический cron.
- Запущенный чат живёт вместе с плагином: перезагрузка плагина (бамп `rev`)
  завершает созданные им сессии.
- Задачи хранят каталог, а не workspace-идентификатор, поэтому задача
  продолжает работать, даже если workspace удалить из списка.
