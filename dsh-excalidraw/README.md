# dsh-excalidraw

Доска **Excalidraw** для каждого чата в DeepSeek Harness. Плагин добавляет
в правую боковую панель (где сейчас открываются файлы) вкладку **Excalidraw**
— общий белый холст: рисует человек в браузере, а агент может читать доску и
рисовать на ней инструментами `excalidraw_read` / `excalidraw_write`.

## Что делает

- **У каждого чата своя доска.** Сцена хранится на хосте по id сессии
  (`$DSH_HOME/excalidraw-boards.json`) и переживает перезагрузку плагина.
- **Доска живая в обе стороны.** Агент рисует через свой инструмент/HTTP —
  открытая вкладка подтягивает сцену сама (опрос раз в 1.5 c), и наоборот:
  штрихи человека сохраняются почти сразу (дебаунс ~0.8 c). Сохраняются только
  **реальные правки** (по версиям элементов), поэтому курсор и скролл не
  затирают то, что нарисовал агент.
- **Вкладка в правом сайдбаре** рядом с файлами: свежий Excalidraw
  (продакшн-сборка из `@excalidraw/excalidraw`, MIT) отдаётся с хоста и
  открывается в iframe. Изменения сохраняются автоматически (дебаунс ~0.8 c).
- **Панель открывается сразу на двух вкладках** — `[Files] [Доска]`, активна
  Files. Сайдбар при разворачивании засевает ровно одну страницу, а при двух
  зарегистрированных типах вкладок вместо файлов показывает страницу-компас
  («Start»). Поэтому плагин **не добавляет себя в компас** (иначе сид стал бы
  компасом), а подкладывает доску рядом с файлами в момент разворачивания
  панели. Плата за это: если закрыть вкладку «Доска», вернуть её можно
  свернуть/развернуть панель (в компасе её нет).
- **Инструменты агента**:
  - `excalidraw_read` — прочитать сцену текущего чата (или указанного
    `sessionId`): все элементы с координатами, размерами, цветами и текстом;
  - `excalidraw_write` — нарисовать: `upsert` (добавить/заменить элементы по
    id, id можно не указывать), `deleteIds` (удалить), `clear` (очистить).
    Агент пишет в ту же доску, которую видит человек, — изменения появляются
    мгновенно.

## Как агенту найти свою доску

Раньше это было настоящей проблемой: у плагина не было ни способа узнать свою
доску, ни даже упоминания о себе, поэтому приходилось искать id сессии через
`env` и читать файл хранилища. Теперь есть три пути, и ни один не требует
угадывания:

1. **Инструменты** `excalidraw_read` / `excalidraw_write` — по умолчанию
   работают с доской **текущего чата** (`exec.agent.session.id`), id передавать
   не нужно вовсе. Это штатный путь для модели.
2. **Из шелла** — в окружении уже есть `$DSH_SESSION_ID`, это и есть текущий чат:

   ```sh
   curl -s "http://127.0.0.1:3080/api/excalidraw/boards/$DSH_SESSION_ID"
   curl -s -X PUT -H 'content-type: application/json' \
        -d '{"elements":[{"type":"rectangle","x":80,"y":80,"width":200,"height":120}],"appState":{}}' \
        "http://127.0.0.1:3080/api/excalidraw/boards/$DSH_SESSION_ID"
   ```
3. **`GET /api/excalidraw/boards`** — список всех досок (`sessionId`,
   `updatedAt`, число элементов), свежие первыми: можно найти нужную, не зная id.
4. **`GET /api/excalidraw/manifest`** — самоописание одним запросом: оба
   инструмента с описаниями, способы найти свою доску, примеры скелетов
   элементов и список маршрутов. Плюс предупреждение: **не присылайте
   `type: "arrow"`** — конвертер Excalidraw ломает скелеты стрелок (они
   возвращаются огрызками); вместо стрелки — линия плюс два коротких штриха на
   наконечник.

Скелеты элементов можно присылать «как есть» (`{type, x, y, width, height}` или
`{type:"line", points}` / `{type:"text", text}`): доска прогонит их через
`convertToExcalidrawElements` + `restore` и сохранит канонический вид.

## Установка

Ссылка на каталог плагина и запись в слой патча профиля:

```sh
git clone https://github.com/westtrade/deepseek-harness-plugins ~/deepseek-harness-plugins
mkdir -p ~/.dsh/profiles/node_modules
ln -sfn ~/deepseek-harness-plugins/dsh-excalidraw \
        ~/.dsh/profiles/node_modules/dsh-excalidraw
```

`~/.dsh/profiles/web/cordis.patch.yml`:

```yaml
- insert:
    - id: excalidraw
      name: 'file:///home/USER/.dsh/profiles/node_modules/dsh-excalidraw/lib/index.js?rev=1'
      config: {}
```

Обновите страницу GUI (без `patchReload: live` — перезапустите `dsh web`).
Вкладка появляется в правой панели рядом с файлами; откройте её для любого
чата.

## Как это устроено

- `lib/index.js` — хостовый плагин: статика (приложение доски и вендоренные
  ассеты Excalidraw) под `/api/excalidraw/*` и API доски
  `GET/PUT /api/excalidraw/boards/<sessionId>`.
- `lib/store.js` — хранилище сцен (один JSON-файл, атомарная запись через
  временный файл + `rename`).
- `lib/client.js` — клиентский плагин: тип вкладки через
  `ctx.sidebarRightTabs.register(...)` и тело/заголовок через слоты
  `sidebar.right.pane.tab` / `sidebar.right.pane.tab.title`. При открытии
  доска **добавляет вкладку файлов в ту же панель** (один раз на чат), так что
  в полосе вкладок появляются оба чипа — «Files» и «Excalidraw» — и
  переключение идёт штатно, без потери доступа к файлам.
- `static/app/` — **приложение доски одним деревом**: `main.jsx` + Excalidraw +
  React, собранные `bun build` (код-сплиттинг для локалей и mermaid) плюс
  `excalidraw.css`. Публикуемая сборка `@excalidraw/excalidraw` не
  самостоятельна — она импортирует десяток npm-пакетов голыми спецификаторами
  (radix, jotai, roughjs, clsx…), поэтому в браузер её отдавать нельзя; граф
  разрешается один раз, при вендоринге.
- `static/assets/` — только то, что Excalidraw тянет по URL во время работы:
  `fonts/` и `data/` (CJK-шрифт ~13 МБ исключён; CJK-текст рисуется системным).
- `static/board.html` — документ iframe: подключает `app/excalidraw.css`,
  `app/main.js`, ставит `EXCALIDRAW_ASSET_PATH` и вешает обработчик ошибок
  **до** загрузки модулей, чтобы сбой показывался текстом, а не пустотой.
- Всё закоммичено — обычная установка ничего не собирает. Пересборка:
  `node scripts/vendor.mjs` (нужны `bun` и `devDependencies` из корня
  репозитория) — после апгрейда `@excalidraw/excalidraw`.

## Безопасность

- Статика отдаётся только из `static/`; выход за её пределы (`..`,
  `%2e%2e`, NUL) запрещён.
- API доски открыто любому вызывающему на том же хосте — это iframe вкладки и
  инструменты агента; «человек или ИИ» разделения для доски не требуется.

## Проверка

```sh
node scripts/host-test.mjs    # API доски, манифест, статика, инструменты: 55
node scripts/client-smoke.mjs # обвязка вкладки, пара «файлы + доска»: 34
npm run test:board            # доска рисуется и принимает правки агента (headless Chrome, нужен живой dsh web)
```

`test:board` стоит запускать после любой правки `static/`: именно он ловит
«страница пустая» (однажды так и вышло — без стилей контейнер доски получал
высоту 33 554 432 px и не рисовал ничего).
