# `dsh-goal-vector`

Векторы целей (ВЦ) для DeepSeek Harness: именованный список целей,
упорядоченный **по приоритету**, которому следует LLM во время работы.
Первая цель — самая важная, последняя — та, от которой отказываются первой.

## Что делает

- **Страница управления** — открывается по строке **«Goals vectors»** в
  сайдбаре (иконка-список). Таблица: колонки **Name**, **Goals**,
  **Actions**; у каждой строки кнопки **Edit** / **Delete**; **Edit**
  разворачивает редактор прямо под строкой — форма та же, что при добавлении
  **Add vector**. В редакторе каждая цель — отдельная строка, порядок меняется
  стрелками **↑** / **↓**, цели можно добавлять и удалять.
- **Селектор в композере** — в ряду инструментов под полем ввода, рядом с
  **Workspace Write**. Показывает, какой ВЦ следует этот чат; пункт
  **«No vector»** возвращает обычный режим (это состояние по умолчанию).
- **Инструменты для LLM** — модель может сама создавать ВЦ, принимать их для
  своего чата и запускать **подагента с ВЦ**.

## Как работает

- **Хранилище** (`lib/store.js`) — один файл `$DSH_HOME/goal-vector.json` с
  двумя разделами: `vectors` (сами ВЦ) и `selections` (какой чат какой ВЦ
  принял). Запись идёт через временный файл + `rename`, а изменения
  **вливаются в текущее содержимое файла**, а не затирают его: при
  перезагрузке патча старый экземпляр плагина какое-то время жив рядом с новым,
  и запись «всей памяти целиком» стирала бы чужие строки.
- **Подстановка в промпт** (`lib/index.js`) — на каждого агента в его
  **собственной области** (`agent.ctx`) регистрируется секция системного
  промпта. Текст читается заново на **каждом шаге** модели, поэтому смена ВЦ
  или правка самого ВЦ действует немедленно, а чаты друг о друге не знают.
  Секция называется `goal-vector:policy` и стоит сразу после `plan:policy`.
- **Рендер ВЦ** — блок `<goals_vector>`: нумерованный список целей плюс прямое
  указание, что при нехватке ресурсов отказываются от целей **с конца**, а в
  отчёте надо сказать, что продвинуто, а что пришлось отбросить.

### Почему выбор чата не хранится в логе сессии

Очевидный путь — записать свой тип события в лог сессии — здесь **нерабочий**.
При восстановлении сессии харнесс сверяется с жёстким списком известных типов
(`KNOWN_SESSION_EVENT_TYPES`) и отказывается читать лог с незнакомым событием;
плагин не может расширить этот список. Такой выбор сделал бы каждый чат, принявший
ВЦ, незагружаемым после перезапуска. Поэтому соответствие «чат → ВЦ» лежит в
собственном файле плагина, а в промпт попадает через секцию, а не через событие.

### Почему именно секция промпта, а не агентский пресет

Пресет агента фиксируется после первого хода и собирается из YAML-файлов на
диске — сменить ВЦ в середине чата им нельзя. Секция в области агента даёт то,
что нужно: смена в любой момент, действие со следующего шага, изоляция между
чатами.

### Особенность загрузки плагинов

Плагин импортирует только `node:`-встроенные модули: плагин, загруженный по
симлинку из рабочего каталога, резолвится в свой реальный путь, где пакеты
харнесса недоступны. Все возможности берутся через внедряемые сервисы
(`webServer`, `sessions`, `agents`, `tools`, `subagents`).

## Установка

```sh
git clone https://github.com/westtrade/deepseek-harness-plugins ~/deepseek-harness-plugins
mkdir -p ~/.dsh/profiles/node_modules
ln -sfn ~/deepseek-harness-plugins/dsh-goal-vector ~/.dsh/profiles/node_modules/dsh-goal-vector
```

```yaml
- insert:
    - id: goal-vector
      name: 'file:///home/USER/.dsh/profiles/node_modules/dsh-goal-vector/lib/index.js?rev=1'
```

### Почему `file://` и `?rev=`

Загрузчик патча прогоняет относительное или абсолютное имя entry через
`pathToFileURL()`, а тот percent-кодирует `?` в `%3F` — модуль «не найден»,
импорт падает, и вся правка патча откатывается на прежнюю копию. Форма
`file://` под перезапись не попадает, поэтому query выживает, а увеличение
`rev` перечитывает весь локальный граф модулей **без перезапуска сервера**.

## Конфигурация (поле `config` строки патча)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `storePath` | `$DSH_HOME/goal-vector.json` | файл хранилища ВЦ и выборов чатов |
| `home` | `$DSH_HOME` | каталог харнесса, если `storePath` не задан |

## HTTP-маршруты (для панели)

| Метод и путь | Назначение |
|---|---|
| `GET /api/goal-vector/vectors` | список ВЦ |
| `POST /api/goal-vector/vectors` | создать ВЦ |
| `GET /api/goal-vector/vectors/<id>` | один ВЦ |
| `POST /api/goal-vector/vectors/<id>` | изменить (можно частично: только `goals`, только `name`) |
| `DELETE /api/goal-vector/vectors/<id>` | удалить ВЦ (и снять его с чатов) |
| `GET /api/goal-vector/selection?sessionId=<id>` | какой ВЦ у чата + список ВЦ |
| `POST /api/goal-vector/selection` | принять ВЦ (`{"sessionId","vectorId"}`, `vectorId: null` — снять) |

## Инструменты для LLM

| Инструмент | Что делает |
|---|---|
| `goal_vector_list` | список ВЦ с целями по приоритету |
| `goal_vector_create` | создать ВЦ |
| `goal_vector_adopt` | принять ВЦ для текущего чата (`null` — снять) |
| `goal_vector_delegate` | запустить подагента, который следует ВЦ с первого шага |

`goal_vector_delegate` передаёт ВЦ ребёнку как его `persona` — подагент
получает цели в свои инструкции ещё до первого чтения, а текст задачи идёт
отдельным промптом.

## Ограничения

- ВЦ **общие для всего деплоя**: их видят все чаты, а выбор — персональный для
  каждого чата.
- Секция промпта не действует в пресете `minimal`: он помечен `complete: true`
  и заменяет системный промпт целиком. В этом режиме ВЦ не подставляется.
- Если ВЦ удалить, чаты, которые его приняли, просто возвращаются к обычному
  режиму — ошибки не будет.
- Выборы чатов хранятся в файле и не чистятся автоматически: строки остаются
  и после удаления чата.
